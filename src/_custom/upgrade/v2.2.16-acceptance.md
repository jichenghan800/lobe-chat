## DEV-051 补充与 DEV-052 强制冻结（本轮验收）

- 新问题轻提示只检测明确换题开场语，例如 “换个话题”“一个不相关的问题”。在当前输入区建议用户使用新问题，支持暂不提醒，当前组件会话内按话题记住关闭；不拦截普通发送、不做任意语义相似度分类、不新增识别模型调用。

- 修正开发者模式下两个入口缺失；底栏由固定 28px 改为最小 28px、按内容增高和换行，避免说明与按钮溢出。

- `topic_cost_freezes` 是服务端独立持久表，话题普通修改、摘要压缩和换模型不能清除冻结；删除话题时由外键级联清理。没有自动解冻、手动高价放行或冻结任务自动迁移。

- 阈值复用提前压缩保护值：min (目录容量 ×50%, 成本预算 ×70%)。当前 Terra 实际为校正后 136,000（原始估算约 108,800）；超过或达到即在上游调用前落库并拒绝。冻结后即使只发 “你好” 仍拒绝。缓存命中对应的输入也计入，不因为缓存较便宜而允许跨过阈值。

- 普通 Chat 请求的话题 Header/Trace、客户端辅助压缩、服务端 Agent/Job 的调用 metadata 均携带 topicId，统一经过 ModelRuntime 冻结守卫。无话题请求仍受单次输入预算约束；外部 CLI 直连不受本守卫控制。已发出的请求无法追回；这是上下文保护，不是每日费用限额，也不宣称停止已在执行的外部工具。

- 输入区读取冻结状态后禁用发送按钮和快捷键；历史和草稿保留。冻结后续接改走服务端专用摘要接口，验证话题归属及消息创建权限，片段≤32,000 字符、前序摘要≤24,000 字符、输出≤4096 Token、无工具。该受限操作可从冻结话题转到新话题，单次预算守卫仍执行，取消信号传到模型请求。

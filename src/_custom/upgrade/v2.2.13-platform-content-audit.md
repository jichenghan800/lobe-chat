# v2.2.13 平台合规审计二开说明

## 业务目标

在 “平台管理” 中恢复旧生产版本的内容审计能力，帮助授权管理员从全平台用户提问中发现需要人工复核的疑似风险内容。

本功能是管理辅助工具，不是自动违规判定系统：关键词或模型结果都只能表达 “疑似风险”，最终判断必须由管理员结合原文完成。

## 与旧版的差异

旧版页面加载时最多对 5 条未分析消息同步调用风险模型，并先取最多 200 条记录再在浏览器分页。新版不保留这两项行为：

1. 列表查询在 PostgreSQL 中完成时间范围、功能类型、风险等级和用户筛选，并使用 20 / 50 条服务端分页。
2. 页面加载只执行规则召回，不自动产生模型费用；模型分析必须由管理员在详情中明确触发。
3. 列表响应不包含用户原始提问，也不显示原文预览。
4. 原文只通过详情 API 返回；每次显式打开详情都会新增一条查看日志，SWR 不跨打开动作复用敏感内容。
5. CSV 只导出当前页的时间、用户、会话、模型、风险等级、风险标签和分析摘要，不导出原文，并防御 `= + - @` 开头的电子表格公式注入。
6. 已完成的历史模型分析优先于规则风险等级；历史分析判定为无风险时，不继续展示旧规则标签。
7. Chat / Agent / Task 不再按 `messages.agent_id` 猜测：以根 `agent_operations` 为准；没有根执行记录的是 Chat，`trigger=chat` 是 Agent，`trigger=task` 是 Task。
8. 用户提问行没有模型时，按 “根执行快照 → 直接助手回复 → 历史用户消息字段” 的顺序回填 provider /model；工具与联网标记从执行记录和助手回复聚合。
9. 搜索文字先保留在输入框本地状态，停止输入 300ms 后才同步 URL 和服务端查询，避免每次按键触发路由刷新造成输入抖动。

## 权限边界

1. `cotti.platformAudit.*` 全部复用 `cottiAdminProcedure`。
2. 授权来源沿用平台管理统一规则：管理员邮箱白名单、全局 `super_admin` 或兼容的 Better Auth 管理员角色。
3. 该管理员角色被定义为全平台审计角色，可以查看个人空间和工作空间中的用户提问；普通用户无列表、详情和分析权限。
4. 查看日志最小记录包括管理员用户 / 邮箱、目标消息、目标用户、会话、时间和来源标识，不复制消息正文。
5. 下列账号不进入审计列表、详情或分析接口：平台管理员（环境邮箱、数据库管理员、全局 `super_admin`、兼容 `users.role=admin`）、`AUTH_ALLOWED_EMAILS` 中的精确邮箱、数据库登录准入中启用的精确邮箱规则。域名准入规则不会整域免审。

## 数据与历史兼容

复用迁移 `0112_add_cotti_platform_tables.sql` 已创建的表：

- `cotti_audit_risk_analyses`：每条消息一个分析结果，`message_id` 唯一；新版继续读取旧结果，并在管理员重新分析时更新同一行。
- `cotti_audit_view_logs`：每次查看原文新增一行，不去重、不覆盖。

不新增表、字段或数据回填。升级前已有分析和查看历史会继续保留；如果目标环境缺少上述表，应先修复 0112 迁移状态，而不是由页面运行时建表。

消息与附件、执行记录、助手回复的关联均在读取时完成，因此历史消息无需回填，也能恢复实际模式、模型和附件信息。免审账号的原始消息、附件和账号不会删除，也不再通过审计接口返回。

精确邮箱准入用户已经产生的 `cotti_audit_risk_analyses` 和 `cotti_audit_view_logs` 属于审计派生数据，应按目标环境中的精确邮箱集合执行一次定向清理；只匹配 `AUTH_ALLOWED_EMAILS` 完整邮箱及数据库启用的 `type=email` 规则，不匹配域名规则，也不因为管理员身份单独扩大删除范围。该清理不做成自动迁移，避免部署时在未核对目标环境名单的情况下执行破坏性删除。

## 风险召回逻辑

默认召回对象只有 `role=user` 的用户提问，不审计模型回复。规则包括：

- 高：疑似密钥 / 凭证、公司机密；
- 中：个人信息、敏感操作；
- 低：包含附件、存在工具调用；
- 无：没有命中规则，或已完成的模型分析明确返回无风险。

规则只影响待复核队列与标签，不产生处罚、阻断、告警通知或用户侧提示。

## 智能分析

1. 配置 `COTTI_AUDIT_RISK_MODEL_PROVIDER` 和 `COTTI_AUDIT_RISK_MODEL` 后，管理员可在详情中主动调用指定模型。
2. 未配置模型时，同一按钮生成本地规则分析，页面仍可正常使用。
3. 送入模型的原文最多 12,000 字符；模型只允许返回结构化摘要、理由、置信度、风险等级、标签和最多 5 条短证据。
4. 模型失败写入失败状态，但不阻断详情和人工复核。
5. 列表刷新、翻页、筛选和打开详情本身均不会调用模型。

## 附件审计

1. 列表只返回附件数量，不返回附件名称、内容或存储 URL。
2. 管理员打开详情后返回附件 ID、文件名、MIME 类型、大小、关联文档及最多 1,200 字符的已提取文本预览；不返回 OSS / S3 URL，也不自动下载原文件。
3. 风险分析同时检查用户提问和已有附件解析文本，总输入仍限制为 12,000 字符，并为附件保留一半上下文预算。
4. 图片、视频及未成功解析的 Excel 等附件只审计元数据，并在详情中明确标记 “未提取到可审计文本”，不伪装成已完成内容审查。
5. 每次详情查看日志额外记录附件数量和附件 ID，不复制附件名称、文本或二进制内容。

## 回归与验收清单

1. 普通登录用户调用三个审计接口均返回 `FORBIDDEN`。
2. 管理员默认看到近 7 天疑似风险记录，可切换 1 / 7 / 30 / 90 天、功能、风险等级和页码。
3. 浏览器列表请求和 CSV 中不包含原始提问。
4. 每打开一次同一消息详情，`cotti_audit_view_logs` 都新增一行。
5. 未配置风险模型时可以打开详情并完成本地规则分析。
6. 历史 `cotti_audit_risk_analyses` 仍显示，重新分析更新同一消息记录。
7. CSV 中以公式字符开头的用户名、会话名或摘要不会被电子表格软件当作公式执行。
8. 深色 / 浅色、空数据、加载失败、刷新和移动端窄屏均可操作。
9. Chat、Agent、Task 分别显示且模型列不为空；历史 Chat 即使保留 `agent_id` 也不能误标成 Agent。
10. 详情展示附件元数据；有解析文本时可展开预览，无解析文本时显示明确状态；附件文本中的风险关键词能进入人工复核信号。
11. 搜索框可连续输入，不会逐字符更新 URL；停止输入后再发起查询。
12. 平台管理员、环境精确邮箱和数据库登录准入精确邮箱无法出现在列表，也不能通过消息 ID 读取详情。

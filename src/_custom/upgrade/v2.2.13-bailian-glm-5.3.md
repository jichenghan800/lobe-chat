# Bailian GLM-5.3 parallel model support

## Goal

Expose `glm-5.2` and `ZHIPU/GLM-5.3` side by side through the existing Qwen/DashScope
provider. Administrators can independently add, enable, order, rename, or remove either model in
平台管理 without rewriting existing agents or changing the current default model.

## Why this is a COTTI adapter

LobeHub v2.2.14 and current canary contain native GLM-5.3 support for the Zhipu provider. The
official implementation defines the model as always-thinking and exposes only `low`, `high`, and
`max` reasoning effort. Alibaba Cloud Bailian serves the same model through its OpenAI-compatible
DashScope endpoint with the marketplace-qualified model ID `ZHIPU/GLM-5.3`.

The shared parameter types, resolver, slider, locale text, and tests in this change follow upstream
LobeHub commits `14ec086c22` and `9130ed27f6`. The COTTI-only delta is intentionally small:

- register `ZHIPU/GLM-5.3` in the Qwen model bank;
- recognize that exact Bailian model ID as thinking-only in the Qwen runtime;
- forward `reasoning_effort` while always sending `enable_thinking: true`;
- keep existing `glm-5.2` configuration and persisted agent rows unchanged.

## Development configuration

Keep both entries in `QWEN_MODEL_LIST`:

```dotenv
QWEN_MODEL_LIST=-all,...,+glm-5.2=智谱-GLM5.2<1000000:reasoning:fc>,+ZHIPU/GLM-5.3=智谱-GLM5.3<1048576:reasoning:fc>
```

Add `qwen/ZHIPU/GLM-5.3` to any legacy visible/display-name allowlists still used by the deployment.
The platform-management model options are generated from the server model list, so both versions
remain independently selectable. Do not replace or migrate `glm-5.2` agent rows for this trial.

## Verification

- model-bank regression verifies the exact provider/model ID and official capabilities;
- parameter-resolver regression verifies always-on thinking and Low/High/Max effort;
- Qwen runtime regression verifies that a stale disabled-thinking preference cannot emit
  `enable_thinking: false`;
- a real DashScope request must use `ZHIPU/GLM-5.3`; unqualified `glm-5.3` is not interchangeable.

## Rollback

Remove the `ZHIPU/GLM-5.3` entry from the development `QWEN_MODEL_LIST` and platform model display
configuration. Existing `glm-5.2` remains available and no database rollback is required.

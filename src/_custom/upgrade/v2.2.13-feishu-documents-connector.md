# COTTI 飞书资料连接器二开说明（v2.2.13）

## 目标

- 落地日期：2026-08-05。
- 用户可见名称统一为 “飞书资料”。
- 内部 identifier 保持 `feishu-documents`，读取工具保持不变，新增飞书官方 MCP `create-doc` 用于把对话内容沉淀为新文档。
- 名称统一不能破坏已存在的个人 OAuth 授权、Agent `plugins` 配置、数据库关系和历史工具调用。

## 为什么此前中英文不一致

连接器详情页通过 `connectorPreset.feishuDocuments.title` 本地化为 “飞书资料”，但预设数据库名称和服务端生成的 ToolManifest 标题仍是 `Feishu Documents`。因此设置页显示中文，而提示词 action tag、模型工具清单和运行记录会继续显示英文。

这不是模型自动翻译导致的，而是两条名称来源没有统一。

## 最终命名规则

| 字段                          | 值                 | 是否允许修改           |
| ----------------------------- | ------------------ | ---------------------- |
| 用户可见名称 / 中文运行时标题 | `飞书资料`         | COTTI 固定             |
| 英文 locale 展示名            | `Feishu Documents` | 由 i18n 提供           |
| Connector identifier          | `feishu-documents` | 禁止修改               |
| Preset ID                     | `feishu_documents` | 禁止修改               |
| MCP 工具名                    | `search-doc` 等    | 飞书协议字段，禁止翻译 |

内部标识和工具函数名属于机器协议，不应该翻译。用户在中文界面看到的连接器标签、插入输入框的工具标签和服务端运行时连接器标题统一为 “飞书资料”。

## 新建文档能力（2026-08-05）

业务目标是把有价值的聊天记录新建为用户自己的飞书文档，不开放对既有文档的任意编辑、评论、消息写入或删除能力。

- 工具白名单新增 `create-doc`；继续禁止 `update-doc`、`add-comments`、消息和删除类工具。
- 使用每个 LobeHub 用户自己的 Feishu User Access Token，新文档以该授权用户身份创建；不改为租户机器人统一身份。
- `create-doc` 可以在 “我的文档库” 或用户指定的知识空间节点中创建文档，并写入本次生成的正文。
- 按飞书官方远程 MCP 要求新增 OAuth scopes：`docx:document:create`、`docx:document:write_only`、`wiki:node:read`、`wiki:node:create`、`docs:document.media:upload`、`board:whiteboard:node:create`；原有只读 scopes 保留。
- 飞书 scope 描述的能力范围大于单一工具，但 LobeHub 服务端仍以 `X-Lark-MCP-Allowed-Tools` 和同步 allowlist 双重限制，只向模型暴露 `create-doc` 这一项写操作。
- 已连接用户的旧 token 不含新增 scopes，升级后必须点击 “重新授权”；仅点击 “同步” 不能补充 OAuth 权限。
- 飞书开放平台后台必须先申请并发布上述权限，否则重新授权或调用 `create-doc` 会失败。
- 本次不开放 `update-doc`。超出 `create-doc` 单次内容上限的超长记录暂不自动续写，后续如确有需求，再单独评估受限追加能力与防误改机制。

## 二开触点

| 文件                                                     | 改动                                                  | 原因                                                      |
| -------------------------------------------------------- | ----------------------------------------------------- | --------------------------------------------------------- |
| `src/const/connectorPresets.ts`                          | 预设规范名称改为 “飞书资料”，增加运行时名称归一化函数 | 单一名称源，同时兼容数据库中已有英文行                    |
| `src/features/ChatInput/ActionBar/Tools/useControls.tsx` | 中文界面选择连接器时使用 i18n 标题                    | action tag 的 `label` 来源于工具选择器标题                |
| `src/libs/mcp/buildConnectorManifests.ts`                | 飞书预设的 ToolManifest 标题强制归一为 “飞书资料”     | 服务端运行不经过客户端 i18n，且历史数据库可能仍存英文名称 |
| `apps/server/src/routers/lambda/connector.ts`            | 继续使用预设名称写入新建或重新连接的记录              | 逐步把历史英文行规范化，无需数据库 migration              |

相关测试覆盖预设稳定标识、旧英文数据库行的运行时归一化、预设创建写入名称，以及中文 action tag 不影响通过 identifier 启用工具。

## 数据和升级影响

- 不新增表或字段，不需要 migration。
- 仅名称统一不要求重新授权；启用 `create-doc` 后，已授权用户需要重新 OAuth，以获取新增的文档创建 scopes。
- 用户下次重新连接时，现有数据库行会更新为规范中文名称。
- 不批量更新历史消息中的 `<tool label="Feishu Documents">`，避免无必要的数据改写；历史消息仍通过 `name="feishu-documents"` 正常识别。
- 下次升级先检查官方是否提供 connector displayName/localization hook；如果已有，保留稳定 identifier，删除本地运行时名称覆盖。

## 验收

1. 设置页、Agent 工具选择器均显示 “飞书资料”。
2. 选中后输入框 action tag 显示 “飞书资料”。
3. 工具运行步骤的连接器标题显示 “飞书资料”。
4. 实际调用仍使用 `feishu-documents____search-doc` 等稳定函数标识。
5. 重新 OAuth 后工具列表包含 `create-doc`，搜索和读取文档仍成功。
6. 明确要求 “把这段对话整理成飞书文档” 时调用 `create-doc`，返回可访问的文档结果。
7. 工具列表不包含 `update-doc`、评论、消息写入或删除类工具。

# v2.2.13 人员管理二开说明

## 目标与边界

平台管理中的原 “Agent 入口” 分区调整为 “人员管理”，统一承载三类相互独立的管理任务：

1. **Agent 入口**：维护 Agent 智能模式入口的显示范围。
2. **管理员设置**：维护可进入平台管理的既有平台用户。
3. **登录准入**：控制哪些新邮箱可以创建账号，并管理已注册账号的登录状态。

人员管理默认打开 Agent 入口，三个页签按上述顺序排列。配置页采用渐进展示：Agent 仅在 “指定用户” 时显示人员列表；登录准入仅在 “指定人员” 时显示邮箱与域名规则，避免无关表单占据页面。

本次不重写认证流程。用户仍在注册页自行设置密码，并按现有 Better Auth 与 SMTP 配置完成邮件验证；密码不由管理员创建或查看。

## 登录准入语义

- 只拦截新账号创建，包括邮箱注册和首次 SSO 建号。
- 已存在账号不受名单删除或停用影响，仍可正常登录。
- 支持指定完整邮箱或整个邮箱域名。
- 数据库尚未初始化时，行为完全由 `AUTH_ALLOWED_EMAILS` 决定；空配置表示开放注册。
- 管理员第一次在页面修改时，将当前 `AUTH_ALLOWED_EMAILS` 自动导入数据库，再以数据库配置为准，避免切换瞬间丢失既有名单。
- 页面不展示容易产生歧义的单条规则 “启用” 列；需要撤销准入时直接删除规则。
- 部署环境生成的只读临时规则也支持直接删除：服务端会先完成首次数据库导入，再按规则类型与规范化值删除对应记录。
- Agent 入口切换为 “全员” 前必须二次确认，确认文案明确说明所有用户都会获得 Agent 智能模式入口。
- 登录准入的 “全部开放” 属于高风险设置，当前在页面置灰并标记暂不可用；服务端既有模式能力暂时保留。
- `AUTH_EMAIL_VERIFICATION`、SMTP、`AUTH_DISABLE_EMAIL_PASSWORD` 等认证基础能力继续由部署环境变量管理。

## 已注册账号登录控制

- “登录准入名单” 继续控制新账号创建，避免删除域名规则时误封该域名下的全部既有员工。
- 平台管理员可在 “登录准入 → 已注册账号登录控制” 搜索具体用户并禁止登录。
- 禁止登录复用 Better Auth 原生的 `users.banned`、`ban_reason` 与 `ban_expires` 字段，不新增平行状态。
- 禁止后立即删除该用户的 Better Auth 登录会话并撤销 OIDC 授权数据；邮箱密码和飞书 SSO 后续登录都会被 Better Auth 拒绝。
- 浏览器端会话缓存最长可能保留 2 分钟，之后必然失效；新登录即时阻止。
- 当前操作人不能封禁自己；平台管理员必须先取消管理员身份再封禁，保留部署级灾备入口。
- 恢复登录只解除封禁，不自动创建会话，用户需要重新登录。

## 平台管理员语义

- 新增的管理员必须是 `users` 表中已经存在的平台用户，页面通过姓名或邮箱搜索选择。
- 数据库管理员通过 `cotti_platform_admin_assignments` 管理。
- `COTTI_PLATFORM_ANALYTICS_ADMIN_EMAILS` 继续作为部署级启动与灾备入口，在页面中只读展示，不允许删除。
- 全局 `super_admin` 与历史 `users.role=admin` 兼容逻辑保持不变。
- 数据库管理员至少保留一名，避免页面误操作清空可维护名单。

## 数据库对象

迁移 `0120_add_cotti_people_management.sql` 新增：

- `cotti_login_access_settings`
- `cotti_login_access_rules`
- `cotti_platform_admin_assignments`

迁移只新增表、外键和唯一索引，不修改用户、账号、会话或历史业务数据，不需要历史用户数据回填。

## 后续升级回放规则

1. 保留 Better Auth 的 `databaseHooks.user.create.before` 单一拦截点，不在登录 API 或多个 SSO provider 中重复增加判断。
2. 保持 “数据库优先、环境变量兜底” 的读取顺序。
3. 不把登录准入与 Agent 入口合并为同一个权限；前者控制建号，后者只控制界面入口。
4. 不把平台管理员直接改写成 Better Auth 管理员或全局 RBAC 角色，避免扩大其上游系统权限。
5. 回归测试必须覆盖环境回退、首次导入、完整邮箱与域名匹配、普通用户接口拒绝和管理员增删保护。
6. 账号封禁必须继续使用 Better Auth 原生字段，同时撤销数据库、Redis 与 OIDC 会话材料，不自行增加第二套封禁状态。

## 验收清单

- 环境变量中既有邮箱 / 域名在首次页面修改前仍然有效。
- 新增邮箱后，该用户能注册、设置自己的密码并完成邮件验证。
- 从准入名单删除后，已注册用户仍能登录，新用户不能再以该邮箱创建账号。
- 禁止一个已注册账号后，其现有会话被撤销，邮箱密码和飞书均不能重新登录；恢复后可重新登录。
- 数据库管理员可以进入平台管理，普通用户得到 `FORBIDDEN`。
- Agent 入口开关继续只影响 Agent 智能选项的展示和可选状态，不影响 Chat 或底层工具能力。

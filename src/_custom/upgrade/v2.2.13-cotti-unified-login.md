# COTTI 产品统一登录（灵枢 OIDC Provider）

## 范围

灵枢 AI 作为 COTTI 产品统一身份提供方，灵境 AI、灵演 AI 与 ComfyUI 作为独立的 OIDC confidential client。用户在灵枢已有有效登录会话时，进入这些产品可自动完成第一方授权；其他官方客户端和第三方 OAuth 应用保持原确认流程。

本二开不新增数据库表或迁移，也不改变飞书登录的授权入口。飞书返回真实邮箱时将其标记为已验证，灵枢再通过标准 `email_verified` claim 传递给下游；飞书未返回真实邮箱时继续使用未验证的占位邮箱，禁止用于统一登录账号绑定。

## 客户端与回调

| 产品    | Client ID             | 回调地址                                                                                                                              |
| ------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 灵境 AI | `cotticoffee-nano`    | `https://nano.cotticoffee.com/api/auth/callback/cotti-sso`、`https://nanodev.cotticoffee.com/api/auth/callback/cotti-sso`             |
| 灵演 AI | `cotticoffee-ppt`     | `https://ppt.cotticoffee.com/api/auth/oauth2/callback/cotti-sso`、`https://pptdev.cotticoffee.com/api/auth/oauth2/callback/cotti-sso` |
| ComfyUI | `cotticoffee-comfyui` | `https://comfy.cotticoffee.com/oauth2/callback`                                                                                       |

两端均使用 Authorization Code + PKCE、`client_secret_basic` 和 `openid profile email offline_access`。两组客户端密钥必须独立生成，禁止混用：

- 灵枢 `COTTI_SSO_NANO_CLIENT_SECRET` = 灵境 `COTTI_SSO_CLIENT_SECRET`
- 灵枢 `COTTI_SSO_PPT_CLIENT_SECRET` = 灵演 `COTTI_SSO_CLIENT_SECRET`
- 灵枢 `COTTI_SSO_COMFYUI_CLIENT_SECRET` = ComfyUI 认证代理 `client-secret`

## 二开触点

1. `packages/env/src/auth.ts` 与 `.env.example`：声明两组可选服务端密钥；缺少密钥时对应客户端不注册。
2. `src/libs/oidc-provider/config.ts`：注册两个静态第一方 confidential client，不开放动态回调地址。
3. `src/features/Auth/OAuthConsent/cottiClients.ts`、`Login.tsx` 与 `Consent/index.tsx`：只对两个 COTTI 客户端自动确认登录和内置授权；桌面端、Market 与第三方客户端不受影响。
4. `src/libs/next/proxy/define-config.ts`：OIDC discovery、JWKS、token、userinfo、introspection、revocation 和 logout 协议端点绕过 Better Auth 页面会话门禁；各协议端点仍由 OIDC Provider 校验客户端或 token。
5. `src/libs/oidc-provider/http-adapter.ts` 与 `provider.ts`：Next.js 对外统一挂载在 `/oidc/*`。Provider 可配置端点显式保留 `/oidc`；只对库中固定的 `.well-known` discovery 路径剥离一次挂载前缀，确保 discovery 宣告的所有端点仍指向外部 `/oidc/*` 地址。
6. `src/libs/better-auth/sso/providers/feishu.ts` 与 `src/libs/oidc-provider/provider.ts`：真实飞书邮箱的验证状态进入 OIDC `email_verified` claim。

## 发布顺序与门禁

1. 在灵枢运行环境写入两组密钥并部署灵枢。
2. 验证 `/oidc/.well-known/openid-configuration` 与 `/oidc/jwks` 返回 JSON，issuer 与当前环境域名一致，不能跳转到登录页。
3. 配置并部署灵境 dev；使用同一 Nano 密钥完成真实登录。
4. 配置并部署灵演 dev；使用同一 PPT 密钥完成真实登录。
5. dev 双端验收通过后，按相同顺序发布生产；生产密钥应与 dev 分离。

缺少任一密钥、下游密钥不一致、issuer 错误或回调地址不匹配都属于发布阻断项。密钥不得提交到 Git、构建参数、日志或验收输出。

## 升级回放与回退

升级时优先保留 OIDC Provider 官方实现，只重放上述静态客户端、COTTI 自动确认边界、协议公开路由与 Feishu email verification 四组小改动。回退时移除两个运行时密钥即可停止注册对应客户端；无需回滚数据库。若下游已切换到统一登录，应先恢复下游原登录方式，再移除灵枢客户端。

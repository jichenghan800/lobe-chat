# COTTI Gemini 3.7 Flash 并行渠道适配

## 目标

- 保留 Vertex AI `gemini-3.6-flash`，新增 `gemini-3.7-flash`。
- 前台始终只展示一个 `COTTI-专业` 渠道。
- 平台管理员选择该渠道实际使用 3.6 或 3.7，普通用户不直接选择底层版本。
- 初始和回退基线保持 `gemini-3.6-flash`，不得在部署时自动切到 3.7。

## 官方实现基线

参考 LobeHub 官方 v2.2.14：

- `14ec086c22113041b92e532703cb1e7027944f19`：新增 Gemini 3.7 Flash 模型卡。
- `5852e0974f01b95f3164cec0a0006de3ff6c5326`：补齐模型描述和运行时覆盖。

本项目只移植当前业务使用的 Vertex AI 路径，没有改动 Google AI Studio 的滚动别名：

- 模型 ID：`gemini-3.7-flash`
- 上下文：1,048,576 输入 + 65,536 输出
- 思考参数：`thinkingLevel3`
- 可选值：`low`、`medium`、`high`
- 官方缺省值：`medium`
- COTTI 模式缺省值：普通 Chat 为 `low`，智能 Agent 为 `medium`
- 禁止发送：`temperature`、`top_p`、旧 `thinkingBudget`
- 保留：搜索、函数调用、视觉、音频、视频、结构化输出、URL Context

特别注意：3.7 不支持 `minimal`。专业渠道从 3.6 切到 3.7 时，历史配置中的
`thinkingLevel=minimal` 必须转换成 `thinkingLevel3=low`，避免 Vertex 返回
`Thinking level is unsupported: THINKING_LEVEL_MINIMAL`。

## 二开边界

官方层只包含模型卡、参数缺省值和兼容性测试。管理员渠道切换是 COTTI 独立能力，主要文件：

- `src/_custom/registry/modelDisplayConfig.ts`
- `packages/database/src/models/cottiModelDisplay.ts`
- `apps/server/src/routers/lambda/cotti/modelDisplay.ts`
- `src/features/CottiPlatformManagement/ProfessionalModelChannel.tsx`
- `src/features/CottiPlatformManagement/ModelDisplaySettings.tsx`
- `src/services/cottiModelDisplay.ts`

未增加新的数据库表或迁移文件，复用 `cotti_model_display_settings` 和现有 `agents` 表。

## 切换语义

管理员在 “平台管理 → 模型展示 → `COTTI-专业` 渠道” 选择版本并二次确认：

1. 服务端确认目标模型已在当前 Vertex AI 部署列表中。
2. 在单个数据库事务中更新 Chat/Agent 的 `COTTI-专业` 映射。
3. 如果专业模型是 Agent 缺省模型，同步更新缺省模型 ID。
4. 同步更新所有当前使用 3.6/3.7 专业渠道的 Agent。
5. 3.6 → 3.7：`thinkingLevel` 转换为 `thinkingLevel3`，`minimal` 降级为 `low`。
6. 3.7 → 3.6：`thinkingLevel3` 转换回 `thinkingLevel`。
7. 历史消息、Topic、用量记录不变；任一步失败则事务整体回滚。

专业渠道在通用模型列表中禁止改名和停用，避免管理员同时从两个入口产生冲突配置。

## 部署配置

Vertex 服务端的 `VERTEXAI_MODEL_LIST` 必须同时声明两个底层候选：

```text
gemini-3.6-flash
gemini-3.7-flash
```

两个模型都声明 `reasoning:vision:fc:video:search` 能力。底层候选使用原始版本名；前台名称由
数据库中的专业渠道统一覆盖为 `COTTI-专业`。完整配置以部署环境的 `.env` 为准。

## 官方速度定位

Google 将 3.7 定位为 “Flash 级延迟和规模下的高级推理”。官方展示的 Box 企业知识工作评估中，
3.7 相比上一版本准确率更高且明显更快；模型卡同时说明思考等级用于平衡质量、成本与延迟，并提示
服务仍可能偶发变慢或超时：

- <https://deepmind.google/models/gemini/flash/>
- <https://deepmind.google/models/model-cards/gemini-3-7-flash/>

因此不能用少量端到端请求推翻模型的官方速度定位。端到端等待还包含隐藏思考、首包排队、联网工具、
网络波动和上游容量；原始生成速度只是其中一部分。

## 真实 Vertex 对比（2026-08-22）

使用当前开发环境 Vertex 项目和 `global` 区域，分别执行串行文本、并发文本、函数调用和
Google Search，共 8 次请求 / 模型：

| 模型             | 成功率 | 文本中位耗时 | 搜索耗时 | 结论                         |
| ---------------- | ------ | -----------: | -------: | ---------------------------- |
| Gemini 3.6 Flash | 8/8    |       1.95 s |   7.99 s | 当前稳定基线                 |
| Gemini 3.7 Flash | 8/8    |       2.55 s |  11.78 s | 该轮端到端小样本等待时间更长 |

该轮统一使用 `medium`，并混合了联网搜索。它只能说明当时这组请求的端到端等待，不代表 3.7 的
模型生成速度低于 3.6。首轮没有复现 ProviderBizError，但小样本也不能排除上游容量波动。因此
3.7 不自动成为缺省，由管理员观察后切换；发生限流或延迟异常时可以立即切回 3.6。

### 模式缺省参数复测

随后使用相同 Vertex 项目、`global` 区域、相同一句话中文问题和 7 个正文输出 token，串行执行
3 次 / 配置。`maxOutputTokens=4096`，避免隐藏思考挤占输出上限：

| 配置               | 首个正文中位耗时 | 总耗时中位数 | 隐藏思考 token 中位数 |
| ------------------ | ---------------: | -----------: | --------------------: |
| 3.6 `medium`       |          2.604 s |      2.664 s |                   245 |
| 3.7 Chat `low`     |          1.919 s |      1.985 s |                   141 |
| 3.7 Agent `medium` |          2.390 s |      2.568 s |                   156 |

在这组可比请求中，3.7 Chat `low` 的总耗时中位数比 3.6 `medium` 低约 25%，3.7 Agent
`medium` 也低约 4%，与官方 “3.7 更快” 的定位一致。样本仍然较小，适合验证参数方向，不作为 SLA。

### Vertex Model Garden 示例参数复核

使用项目运行时实际加载的 `@google/genai 1.52.0`，按 Vertex 示例参数执行真实请求：

- `maxOutputTokens: 65535`
- `thinkingConfig.thinkingLevel: MEDIUM`
- 四类 Safety Settings 为 `OFF`
- 同时启用 `googleSearch`、`googleMaps`
- `toolConfig.retrievalConfig.languageCode: zh_CN`

请求成功，首包 8.54 秒，总耗时 9.10 秒。说明 SDK 1.52.0 已能正确提交 3.7 及上述参数，
不需要为了模型 ID 升级 SDK。

本项目接入时的取舍：

- 智能 Agent 的 `thinkingLevel=MEDIUM` 与示例一致；普通 Chat 缺省改为 `LOW`，降低首包延迟。
- 模式缺省值只在用户未显式设置 `thinkingLevel3` 时生效；用户手动选择的等级不会被模式切换覆盖。
- `enableAgentMode=false` 明确代表 Chat；`true` 或未设置沿用项目既有语义，代表 Agent。
- 模型卡继续采用 LobeHub 官方的 `maxOutput=65536`；实际请求只有用户启用输出上限时才显式
  发送 `maxOutputTokens`，否则由 Vertex 使用模型缺省值。
- 保留 LobeHub 公共 Google Runtime 的 Safety Settings，不增加 3.7 专属分支。
- 联网搜索继续按用户开关发送 `googleSearch`。
- 不把 `googleMaps` 和 `zh_CN retrievalConfig` 强制加到所有请求：地图 Grounding 是不同能力，
  会改变费用、隐私边界和延迟，后续如产品需要应单独增加显式开关。

### GenAI SDK 版本

- 根应用依赖：`@google/genai 1.50.1`
- `packages/model-runtime` 实际依赖：`@google/genai 1.52.0`
- 2026-08-22 npm latest：`2.18.0`
- 同期 LobeHub 官方 main/canary：仍为根应用 `1.50.1`、Runtime `1.52.0`

2.x 是 SDK 大版本升级，超出本次模型新增范围；官方 3.7 提交也没有升级 SDK。当前真实请求已通过，
因此保持与 LobeHub 官方一致，避免引入与 3.7 无关的运行时回归。

## 验收重点

1. 未切换时，前台 `COTTI-专业` 仍使用 `gemini-3.6-flash`。
2. 管理页同时显示 3.6、3.7 两个底层候选，但普通用户只看到一个 `COTTI-专业`。
3. 切到 3.7 后，新旧专业 Agent 均使用 3.7；未手动指定思考等级时，Chat 请求发送 `low`，
   Agent 请求发送 `medium`，且都不包含 `minimal`、`temperature` 或 `top_p`。
4. 切回 3.6 后不需要重新构建镜像，现有 Agent 立即恢复 3.6。
5. 分别验收普通对话、Agent 工具调用、联网搜索和长上下文，不只检查简单问答。

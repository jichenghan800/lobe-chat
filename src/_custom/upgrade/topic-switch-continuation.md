# 换题判断：先确认指令能否独立执行

## 2026-09-20

问题：字面相关性不足以区分续接和新任务；“请重试” 等原先会进入辅助模型，
“换个话题……” 又会绕过模型直接提示，可能把仍依赖历史的操作移到空话题。

最小改动：

- 独立二开模块 `src/_custom/topicSwitchPolicy.ts` 提供完整短句的保守续接规则及判断提示词。
- 客户端和服务端共用短句规则；重试、续接、引用已有方案 / 结果等明确指令不发起模型推理。
- 其他输入沿用一次辅助模型调用，同时返回 standalone/unrelated；仅两项均严格为 true 才建议换题。
- 模型不确定、字段缺失、格式异常、调用失败均保持当前话题。
- 移除仅凭 “换个话题” 前缀就弹框的 shortcut 及对应孤立文件；完整输入仍需独立性判断。
- 仍只传最多 200 字符的概览和 1000 字符的新输入，不读取历史消息，不更换模型或改变价格、权限。
- “帮我写工作总结” 缺少细节但可独立起题；“把它缩短一点” 依赖前文。
- “继续，另外查询北京天气” 不因开头 “继续” 被硬规则截断。

接口对客户端仍返回 boolean；仅内部辅助模型结构化输出增加 standalone。无数据库迁移。

## 验证

58 项相关回归通过。以旧客户端 / 服务端实现运行新增回归：15 项失败，证明覆盖了旧逻辑。
完整 TypeScript 检查通过。真实模型判断属于概率行为，结构化门槛降低误弹，不承诺完全无误判。

## 升级边界

官方 SystemAgentService 只接入 helper、短路及结构化输出门槛；
客户端原有发送 / 弹框 / 缓存 / 超时路径保持不变。后续官方覆盖该能力时，
先运行 topicSwitchPolicy、topicSwitchCheck、systemAgent/topicSwitch 三组回归再移除二开。

发布后使用已登录浏览器调用真实辅助判断接口：请重试、还是不对、按照第二个方案、
换个话题请继续上面的分析、刚才结果遗漏重新检查均为 false；
查询北京明天天气、继续另外查询北京明天天气均为 true。全部 HTTP 200。
其中 3 条由保守规则短路，其余 4 次使用现有辅助模型；不发送正式消息。

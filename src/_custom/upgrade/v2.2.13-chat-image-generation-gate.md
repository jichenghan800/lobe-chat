# v2.2.13 Chat 生图工具准入收紧

## 背景

LobeHub 官方提交 `3dfa62a01d6`（`#15332`）开始在 Chat 模式下，为所有支持函数调用、但不支持原生图片输出的模型默认注入 `lobe-image-generation`。在 COTTI 使用的 Gemini Flash 模型上，模型会把普通文本任务误判为生图任务，例如查询邮件、写入飞书文档、查询沟通记录或解释验证码过期。

2026-08-10 对 chatdev 真实消息记录的诊断确认：用户输入 “提示过期了” 后，`gemini-3.6-flash` 直接调用 `generateImage`，并继续查询生图模型、参数和状态；历史上 `gemini-3.5-flash-lite` 也存在同类误调用。

## 二开决策

- Chat 模式不再默认启用 `lobe-image-generation`。
- 用户本轮明确选择生图工具时，仍通过 `selectedToolIds` 放行。
- 用户本轮选择 Gmail、飞书资料等连接器时，只放行明确选择的连接器，不附带生图工具。
- Agent 模式的工具发现、显式激活和图片生成能力保持官方行为，不做修改。
- 图片生成执行器、模型列表和生成结果渲染保持官方实现，不增加额外执行逻辑。

## 行为矩阵

| 场景                                   | 生图工具                     |
| -------------------------------------- | ---------------------------- |
| Chat 普通文本对话                      | 不注入                       |
| Chat 明确选择 `lobe-image-generation`  | 注入                         |
| Chat 明确选择 Gmail / 飞书资料等连接器 | 不注入生图，仅注入所选连接器 |
| Agent 模式                             | 保持官方工具发现与激活逻辑   |

## 代码边界

- `src/helpers/toolEngineering/index.ts`：客户端 Chat 工具白名单不再默认开启生图工具。
- `apps/server/src/modules/Mecha/AgentToolsEngine/index.ts`：服务端 Chat 工具白名单保持相同约束。
- 两侧继续使用已有的 `selectedToolIds` 显式工具准入链路，避免增加关键词识别或额外意图分类逻辑。

## 回归测试

- Chat 模式默认不启用生图工具，即使当前模型支持函数调用且不支持原生图片输出。
- Chat 模式显式选择生图工具后可以正常启用。
- Chat 模式显式选择其他连接器时不会夹带生图工具。
- Agent 模式默认与显式激活生图工具的原有测试保持通过。

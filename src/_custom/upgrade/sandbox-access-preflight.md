# 沙箱发送前授权与显式兜底

## 2026-09-20：范围与原因

官方 v2.2.17 的沙箱路由主要依赖上游鉴权错误转成 401，再由浏览器触发社区授权。普通 Forbidden / 安全检查 403 不会触发此流程；服务端 Agent 也不能依赖浏览器工具请求的错误拦截。生产补验发现当前用户无社区凭据，同时生产到 Market 公共页返回安全检查 403，两个问题不能混为一谈。

## 本次二开

- 新增隔离的 `src/features/SandboxAccess/`，只在首页智能 / 任务及普通话题的直接发送入口调用。打开话题、切换模式不弹框；云端入口在已确认未登录时显示 “待授权”。
- `cotti.sandbox.preflight` 使用当前登录用户的服务端凭据检查社区身份，不创建沙箱、不调用模型、不返回凭据。缺凭据 / 明确 401 提示登录；403、超时或其他失败提示服务暂不可用。检查最多等待 8 秒，可信客户端模式保持原语义。
- 复用原有社区登录流程；成功后再次检查，再继续待发送内容。失败或取消后可明确选择自建沙箱，不静默切换。不清空输入和附件，不代用户完成第三方授权。
- 自建沙箱不要求社区登录。原有欢迎提示排除自建沙箱；自建入口仍使用已有平台签名、权限与容量控制。
- 兜底切换前重新检查容量，仅作提示；真正分配仍由原子名额控制完成，所以并发抢占仍可能在执行时拒绝。不能把预检当作预留名额。
- 已用云端话题仍走服务端 `switchUnusedTopic` 保护：无执行记录可原地切换；已有执行或结果不确定必须经用户确认新开话题，仅带入当前输入及附件，不迁移云端临时文件。运行中的话题不切换。
- 授权期间用户改文字、附件、上下文选择、切话题或离开首页，不继续发送旧请求。二次换题保留选择的沙箱类型。

## 边界

- 非交互的后台任务、正在运行的工具循环、群组 / 子线程、桌面或指定电脑执行不新增浏览器弹框。此补丁不声称覆盖所有运行中授权失效的恢复路径。
- 自建沙箱不能替代官方托管连接器、Cloud MCP 或社区发布等账号能力。
- 不改变上游访问网络、不修改账号绑定、不自动清除社区凭据。生产访问 Market 的 403 另行处理。
- 发布目标为两个共享开发入口；生产本轮不更新，也不自动启用生产 OnlyBoxes。

## 验证

控制器、Hook、服务端鉴权分类及首页发送回归覆盖取消、失败、显式兜底、满额、已用话题、新旧自建话题、电脑目标、离开页面等分支。首页新增两项取消回归在旧实现均失败。47 项相关回归及全仓类型检查通过；完整构建通过。

可见 Chrome 实测：进入智能模式不弹框；发送时出现社区授权提示；取消保留文字和附件；取消社区授权后可明确选择自建沙箱。真实小任务上传 TXT、Python 读取并计算 7×8、写入文件并导出成功，下载接口返回 200 且文件内容正确。服务端确认话题提供方为 OnlyBoxes，账号仍无社区 accessToken。未重跑用户业务任务。

验收任务首次使用相对路径导出失败，模型改为绝对路径后成功；此为已有文件路径行为，不列为本补丁已修复问题。本轮未完成真实社区 OAuth 成功回调，成功重检分支由回归测试覆盖。满额和已用云端话题新开保护也仅做自动化回归，不声称全部端到端覆盖。

独立代码复核后补齐电脑执行目标识别、授权等待期间附件变动保护，以及新话题接受后导航的并发保护。

升级时优先比较官方发送前鉴权和沙箱 provider 感知的授权提示；官方覆盖后可移除发送入口挂钩及本目录隔离模块，保留用户选定沙箱和服务端文件保护语义。

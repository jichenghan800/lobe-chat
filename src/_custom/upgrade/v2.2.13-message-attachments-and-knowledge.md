# COTTI 消息附件与 Agent 知识二开说明（v2.2.13）

## 记录目的

- 基线：官方 LobeHub `v2.2.13`。
- 落地日期：2026-08-05。
- 目标：把 “本次消息临时使用文件” 和 “长期加入 Agent 知识” 拆成两个可理解、可验证的动作，避免大表格在 Agent 获得工具调用机会前被全文塞入模型上下文。
- 升级原则：新增能力优先放在 COTTI 文件；只有附件入口、草稿状态、Agent 知识关系和运行时上下文等无法旁路的边界才修改官方文件。

本文是后续升级必须逐项回放的二开清单。不能仅依据 Git 冲突判断是否需要移植。

## 产品语义

### 随消息发送

- 来源可以是本地文件，也可以是 “资料库” 中的既有文件。
- 文件显示在用户手动上传文件的同一附件区域。
- 只建立本次消息与文件的关联，不自动加入当前 Agent 的长期知识。
- 从资料库复用时不重新上传，移除草稿附件也不删除资料库原文件。

### 添加为知识

- 只在可配置当前 Agent 资源时显示。
- 建立 Agent 与文件或知识库的长期关系。
- 启用单个文件时显式启动解析和分块任务，并遵循服务端 `CHUNKS_AUTO_EMBEDDING` 配置自动向量化，不能只建立关系而留下没有 chunks 的 “空知识”。
- 关闭知识只解除启用状态，不重新解析文件。

## 行为矩阵

| 场景                                                                   | 当前行为                                                    | 是否注入完整正文 | 是否分块 / 向量化                        |
| ---------------------------------------------------------------------- | ----------------------------------------------------------- | ---------------- | ---------------------------------------- |
| Chat 上传普通文档                                                      | 保留官方上传和直接读取                                      | 是               | 否                                       |
| Chat 上传单个小型、单有效 Sheet Excel                                  | 保留官方直接读取                                            | 是               | 否                                       |
| Chat 上传大于 128KB、多份 Excel、多个有效 Sheet 或无法安全检查的 Excel | 文件照常上传并显示，但 Chat 禁止发送；切换 Agent 后直接复用 | 否               | 否                                       |
| 从资料库 “随消息发送” 普通文件                                         | 复用原 file id/URL，显示在附件区                            | 按官方 Chat 规则 | 否                                       |
| 从资料库 “随消息发送” 表格                                             | 统一要求 Agent 模式                                         | 否               | 否                                       |
| Agent / 异构 Agent 发送 XLS/XLSX/XLSM/XLSB/CSV                         | 仅传文件元数据和可访问 URL，由运行环境工具读取原文件        | 否               | 否                                       |
| “添加为知识” 启用文件                                                  | 建立 Agent 关系并启动知识处理任务                           | 运行时按知识检索 | 分块；`CHUNKS_AUTO_EMBEDDING=1` 时向量化 |

从资料库选择的表格统一要求 Agent，是因为前端拿到的是文件元数据和 URL，没有本地 `File` 内容，无法在不下载整个文件的情况下可靠检查工作簿大小与 Sheet。该限制属于有意的保守策略。

## 数据落点与历史数据

- `files`：上传文件的唯一持久化记录。普通消息附件和知识文件都会存在这里，因此 “文件出现在资料库” 不等于 “已经成为知识”。
- `messages_files`：本次消息使用了哪些文件。
- `knowledge_base_files`：文件与知识库的关系。
- Agent 文件关系：由现有 Agent knowledge service 维护。
- `documents` / `chunks` /embedding 状态：只有知识处理任务或官方解析流程真正执行后才会产生。

本次不新增表、不改 schema、不需要数据库 migration。历史 `files` 数据保持不变；旧文件只有在管理员或 Agent 所有者明确执行 “添加为知识” 后才启动知识处理。

## 与官方代码不同的触点

### 新增、集中维护的 COTTI / 独立文件

- `src/features/LibraryModal/SendFiles/*`：资料库文件选择器，只负责 “随消息发送”。
- `packages/utils/src/spreadsheet.ts`：前后端共享的表格类型判断，避免客户端和服务端规则漂移。
- 本文档：记录业务语义、官方触点、回放顺序和验收标准。

## 双层保护逻辑

1. 客户端在普通 Chat 检查本地 Excel：超过 128KB、多文件、多有效 Sheet 或检查失败时，上传但标记为 `requiresAgentMode`，跳过正文解析。
2. Conversation 与 Home 的提交边界阻止这类草稿通过普通 Chat 发送。
3. 服务端根据最终 Agent 配置（含 workspace member mode override）决定是否启用 `metadataOnlySpreadsheets`。
4. Context Engine 在 Agent 模式最终构造消息时再次移除所有表格正文，只保留 ID、名称、MIME、大小和 URL。

服务端策略默认值必须保持 `false`。否则普通 Chat 的小表格原生直读能力会退化。

## 下一次官方升级的回放顺序

1. 先确认官方是否已经区分临时附件与长期知识，以及 Agent 是否已对表格采用工具读取。
2. 运行本文件的行为矩阵；官方已覆盖且语义一致的部分直接删除二开，不做重复实现。
3. 先移植共享表格判断和草稿类型，再移植 file store。
4. 移植服务端附件策略和 Context Engine 双层保护。
5. 移植 “随消息发送 / 添加为知识”UI，最后接入 Conversation/Home 提示。
6. 检查所有官方触点是否改名或迁层，尤其是 `resolveRunAttachments`、`resolveAttachmentsByFileIds`、ChatInput 两条发送链路。
7. 逐项执行验收，不得只验证 TypeScript 编译。

## 验收清单

- 本地 PDF/TXT 上传后可见、可在 Chat 正常发送。
- 单个小 Excel 单 Sheet 在 Chat 保留官方直读能力。
- 大 Excel 在 Chat 上传完成后仍显示；按钮和 Enter 都不能发送；切换 Agent 后无需重传即可发送。
- 首页存在受限表格时明确提示且不丢草稿。
- Agent 首次模型请求中不包含 XLS/XLSX/CSV 的完整解析正文，但保留文件 URL 和元数据。
- Agent 使用代码 / 文件工具可以读取原表格。
- 从资料库选择文件后显示在手动上传附件位置；移除草稿不删除源文件。
- “添加为知识” 后文件产生成功的 chunk 状态；启用 `CHUNKS_AUTO_EMBEDDING` 的环境还需产生成功的 embedding 状态；移除知识不删除普通消息附件。
- Chat 小表格、Agent 表格、bot/IM 表格三条入口均有回归测试。

## 生产审计建议

发版前只读检查：

1. 抽样统计已关联 Agent 的文件是否存在长期处于 pending/error 的 chunking 或 embedding 状态。
2. 用大表格在 chatdev 验证首次模型请求未出现完整表格正文。
3. 检查消息附件关系和 Agent 知识关系数量，确认 “随消息发送” 没有误增知识关系。
4. 对旧版已关联但没有 chunks 的 Agent 文件，只生成诊断清单；未经确认不做批量回填。

## 数据库迁移与演练

生产原有 154 条迁移记录，历史二开时间戳晚于官方新迁移。直接启动官方迁移器会跳过部分增量，因此私有 `reconcile.sql` 按原始 SQL 哈希补齐：

1. 0158：文件上传预留。
2. 0159：任务活动。
3. 0160：验收资源。
4. 0161：验收评论。
5. 0162、0163：本次二开迁移的幂等补齐。

SQL 核对生产历史哈希，使用单事务、固定 public search\_path、5 秒锁等待和 120 秒语句超时；不重写既有迁移文件。隔离副本连续执行两次成功。显式 search\_path 避免管理员角色默认 schema 与应用 public schema 不同。

隔离网络禁止外部访问，使用独立 PG 与 Redis，阻断真实邮件、模型、Market 和调度请求。新版、旧回退镜像分别连接升级后的数据库副本，通过临时副本会话验证六项管理接口：管理员权限、模型管理、统计概览、话题预算、全览列表、人员管理。共 12 项 HTTP 200；临时会话已清理，演练容器已停止。

初期演练的端口连通及 Redis 登录错误来自隔离环境配置，修正后重测通过；不是应用代码补丁。

## 回退

`release.py` 默认只读预检，`--execute` 执行固定发布包的切换；发布失败会尝试恢复旧应用。准备包的文件和环境摘要改变后，禁止直接复用。

已发布后的应用回退，在生产主机执行：

```bash
python3 /opt/lobechat-releases/v2217-20260913/release.py --rollback --execute
```

回退保留升级后的数据库及发布后新增数据；不自动恢复数据库归档。旧镜像与新 schema 的六项管理读取已在副本中验证，但不代表新版新建的所有官方验收对象可在旧界面完整展示。

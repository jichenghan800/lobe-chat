# 自建沙箱容量管理（2026-09-14）

用户已选择：即时生效，只限制新建会话，保留正在使用的沙箱。本文只记录本次方案，取消维护窗口应用的备选设计。

## 实际实现

平台管理增加 “沙箱管理”，管理员可填写 1～100 个会话，回车或失焦自动保存，显示保存状态和失败重试。默认 2 个；开发环境目标 5 个，各环境独立配置。

新建 OnlyBoxes 会话前，平台在 PostgreSQL 事务内申请名额。锁定同一配置行，避免多个应用进程超发；同一服务、用户、会话共用一个名额，不同用户相同话题标识不共用。配置与占用持久化，应用重启不清零。

增加上限在下一次申请生效。降低上限不删除现有名额，不重启 Worker，不销毁已有容器；例如 5 降至 2，已有会话可继续，占用低于 2 后才允许新会话。满额返回明确工具错误，不静默转至官方云端。

页面的 “保留名额” 包含已申请和租期内会话，不是 Docker 实时运行数量。名额按请求租期、命令超时及 60 秒缓冲保守保留；网络失败不会立即释放，不同并发响应不会缩短租期。明确拒绝的新申请可按版本号释放，已被其他并发请求复用的名额不释放。因此容器已退出后，名额可能仍短暂保留。

## 接入边界

- 当前正式运行环境仍使用官方 Market，页面明确显示自建沙箱未启用；保存容量不等于启用 OnlyBoxes。
- 本次不增加并列的运行环境选择，也不解决长任务自动续租。这两项属于后续接入工作。
- OnlyBoxes 0.11.0 的原生数量上限只在 Worker 启动时读取。正式接入时须统一平台与 Worker 的准入边界：受控私有 Worker 设置 `WORKER_TERMINAL_MAX_ACTIVE_SESSIONS=0`，由平台独占准入；不能保留较低 Worker 硬上限却宣称页面已经扩容。
- Console 不对用户开放，不提供绕过平台的执行入口；平台数据库不可用时拒绝新执行。共用一个 Worker 的应用必须共用此配置与名额数据库；独立数据库须使用独立 Worker。
- 名额过期依赖 Worker 按租期清理的约定。部署使用原生租期下限 60 秒，不能额外配置高于平台请求的最低租期。原生 Worker 仍会在到期时终止命令，完整接入前须验收长任务续租。
- 本次迁移新增两张表，不修改已有用户、话题或任务记录。迁移编号 0164。

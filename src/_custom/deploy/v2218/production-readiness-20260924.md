## 正式切换顺序

1. 传输固定镜像包，校验哈希；新建生产专用私有发布目录。保存实际容器、环境、网络、Nginx、QStash 配置及摘要；不得套用开发环境配置或数据库。
2. 从生产最新在线备份恢复到独立、无网络、无对外端口的副本，验证官方补齐迁移和新增二开迁移；确认二开配置与业务数据保留，并验证旧镜像对升级后副本的必要读取。仅操作副本。
3. 制作生产专用切换脚本，默认只读预检。`reconcile_copies.py` 仅允许固定隔离副本，禁止改参数指向在线生产；生产迁移执行须另行校核固定 SQL 哈希、实际历史与事务范围。
4. 取得生产切换确认后，进入维护，暂停生产现有调度，检查运行中 Agent / 上传 / 异步任务，待安全停止后获取最终停写备份。归档旧静态资源，保留旧容器配置及镜像。
5. 在最终生产数据上执行已演练迁移并启动候选；不得用准备期或开发库覆盖生产数据。保留生产认证域名、模型渠道、OSS、Redis、QStash、OnlyBoxes、WARP 路由及资源限制。
6. 健康和配置核对通过后开放入口，恢复原有调度，确认没有重复计划。使用管理员新话题验证登录保留、实际模型、管理全览、沙箱执行和附件下载，观察重启与错误情况。
7. 若失败，先保持维护并保存现场；按已验证范围回退应用，保留当前数据库新增数据。禁止直接用旧备份覆盖发布后的新写入，也不能把带旧数据库配置的历史容器直接启动当作回退。

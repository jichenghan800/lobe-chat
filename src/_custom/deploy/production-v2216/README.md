## 为什么需要兼容迁移

生产有旧二开迁移 0120，时间戳高于部分新版官方迁移。直接运行新镜像会跳过缺失的 `projects` 等表，随后启动失败；现存准入 / 管理员表又与 0158 创建操作冲突。

`build-reconcile.py` 读取原始 0131–0165，生成单事务 `reconcile.sql`，按原文件哈希补齐。检查已核实的生产谱系；0158 必须与已保存的列、约束、索引结构完全一致才接纳；0132 若发现未登记标签表则拒绝执行原生 DROP。原始官方迁移文件不作修改，成功后登记原哈希，重复执行不重复迁移。任何不符均停止，不能手工绕过检查。

```bash
python3 src/_custom/deploy/production-v2216/build-reconcile.py > /私有发布目录/reconcile.sql
```

## 配置与用户影响

保留生产数据库、密钥、对象存储、模型凭据、普通 / 蓝版飞书和域名；不复制开发库用户，也不合并两个系统的数据。继续使用 Docker PG /pg\_search 和现有 QStash。

候选配置仅调整：

- 数据库连接显式 `search_path=public`；搜索 `pg_search`，开启增量同步。
- 邮箱验证码开启、Magic Link 关闭，沿用生产 SMTP。
- 自动命名与描述、换题判断使用快速模型 `vertexai/gemini-3.5-flash-lite`；其他辅助模型配置保留。
- QStash 复用现有 dispatcher ID，允许新版按原生逻辑登记调度；回滚脚本恢复旧 10 分钟 dispatcher，删除本应用新版 goal sweep。
- 按已确认规则补齐 Sol → Terra 替换，保留历史消息实际模型与计费归属。

**费用保护默认每话题 10 元，包含已记录历史费用，并在发送前预估本次费用。** 备份中 132 个话题历史费用已达到 10 元，其中 13 个自 9 月 6 日起仍活跃。发布不会批量冻结；再次请求时会检查额度。管理员可给大任务设置单话题临时额度，或调整 / 关闭平台默认保护。预算是估算，不是跨并发请求的原子扣款，无法承诺严格零超支；缺失历史费用也不会伪造补算。原生上下文压缩逻辑不变。

## 切换步骤（已执行，勿重复执行）

选择低峰窗口，通知用户短暂中断，确认正在运行的任务已结束。由操作人员在生产服务器执行：

```bash
# 只读检查，可重复执行
python3 /opt/lobechat-releases/v2216-20260911/release.py

# 正式切换：仅在决定上线后执行
python3 /opt/lobechat-releases/v2216-20260911/release.py --execute
```

脚本核对基线与全部校验和、拒绝近期仍运行的 Agent，然后停止应用，重新备份最新数据库及配置，验证备份可读，执行兼容迁移、旧 Agent 名单恢复、Sol 替换及费用汇总；只重建应用，保存解析后的生产 Compose，确保以后重建仍用新镜像；检查应用健康并重载 Nginx。数据库、QStash、其他业务容器不重建。

切换会产生应用停机窗口，最终备份及迁移耗时决定长度，不承诺零停机。QStash 不停止；验收时检查停机期间消息重试和是否重复执行。

切换后的人工验收顺序：

1. `chat.cotticoffee.com` 独立域名不跳转 chatdev；普通 / 蓝版飞书与邮箱验证码登录。
2. 原用户、历史话题、附件与对象存储；管理页人数、全用户话题检索和费用。
3. 普通 / VIP 模型与 Agent 授权；Sol 不可调用且遗留引用转 Terra；少量真实回复。
4. 10 元默认额度、发送前检查、单话题额度与解冻；不使用客户大任务作破坏性测试。
5. QStash 调度 destination、任务执行、暂停规则；无重复 dispatcher，其他业务无影响。
6. 观察应用错误、重启次数及费用，确认后关闭发布窗口。

## 回滚

切换过程中失败会尝试恢复旧 Compose / 镜像、检查健康、重载 Nginx 并恢复原调度。也可人工执行：

```bash
python3 /opt/lobechat-releases/v2216-20260911/release.py --rollback --execute
```

应用回滚保留升级后的数据库，避免丢失切换后新数据；旧镜像已通过克隆启动 / 读取验证。若涉及数据损坏，应先停止写入、另外备份当前库，再评估定点恢复；**不得直接用旧 dump 覆盖仍在使用的生产库**。最终备份在生产发布目录 `cutover-backup-*` 下。发布包包含凭据，仅 root 可读，发布稳定前保留。
